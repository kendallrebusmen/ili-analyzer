# ILI Analyzer — Milestone 5 (Growth Rates) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compute every spec §6.5 growth method for every current-run metal-loss feature in the M4 match table, select the governing rate by a configurable rule, and record which method governed. Write `growth.csv`, `growth_segments.csv`, and `growth_summary.json`. Report the bias and RMSE of estimated vs true growth and the conservatism rate (governing ≥ true for ≥ 90% of features, a PLACEHOLDER target) on synthetic data into `outputs/validation_metrics.json`.

**Architecture:** `src/ili/growth.py` reads the M4 match table and works in three stages:
1. Per-feature methods, vectorised over rows: `raw`, `tolerance_adjusted`, `new_feature`, `full_life`, `default_rate`.
2. Segment methods: `segment_percentile` over the segment table, plus per-segment diagnostics.
3. The governing rate from a settings rule chosen by history class, plus length growth.

Reference lookups by current-run log distance (pipe properties, segments) move into a small shared `src/ili/reference.py`, which `match.lookup_od` then uses. `validation.score_growth` scores the result against ground truth.

**Tech Stack:** pandas 3.x, numpy, pydantic config.

**Spec:** `docs/SPEC.md` §6.5, §7.1 (`tool`, `growth`), §8, §9 M5, §10.2 and §10.4 (open questions: tool tolerances, growth method; values stay PLACEHOLDER). Inputs: the M4 `match_table.csv`, M2 standardized CSVs (run dates), `reference/pipe_properties.csv` (`install_year`, `wt_nom_in`), `reference/hca_segments.csv`, and M1 `ground_truth.csv` (`growth_mpy`).

## Global Constraints

- All M1–M4 constraints hold. Every tuning value lives in `config/settings.yaml` with a comment, there are no magic numbers in `growth.py`, and every output carries `DRAFT – for review by qualified personnel.`
- Units: depth in inches = `depth_pct / 100 × wt_nom_in`, using the **current-run** joint wall (`curr_wt_nom_in`, falling back to `prev_wt_nom_in`). Rates are in mpy (mils/yr = in/yr × 1000). Δt is in decimal years via `match.delta_t_years`. Length rates are in in/yr.
- σ per run = `units.sigma_from_tolerance(tool.depth_tolerance_pct_wt, tool.depth_certainty)`, in % of wall. Both runs use the one `tool` block (spec §10.2 is open). σ_diff = √(σ_prev² + σ_curr²).
- Growth applies to `metal_loss` rows that have a current side: `matched_1to1`, `matched_cluster`, and `new`. Dents, gouges and `missing` rows get no growth row. A cluster row uses its envelope depths (the match table's max depths).
- Reference tables are keyed to current-run log distance. A feature's reference position is `curr_log_dist_ft`.
- Outputs go to `outputs/<prev>_vs_<curr>/`, and metrics merge into `validation_metrics.json` under `growth`.
- Every method's inputs and result are columns in `growth.csv` (spec §2 traceability).

## Review Focus

1. **Missing inputs:** a feature with no wall, no depth on one side, or a NaN segment. The affected methods are NaN, the governing rate comes from the methods left, and a feature with no usable method has a NaN governing rate and `needs_review` True. Never a crash or a silent 0. Test in Task 3.
2. **New pipe:** a feature in pipe installed after the previous run (the replaced section, `install_year` > previous run year). Its history class is `no_history`, not `new` (it was never below threshold in the previous run; the pipe wasn't there), and `full_life` uses the new install year. Test in Tasks 2 and 3.
3. **`full_life` with `install_year ≥` the current run year:** NaN, never inf or negative. Test in Task 2.
4. **`default_rate_mpy: null`** (the shipped value): `default_rate` is NaN and drops out of the max. With no other method, the governing rate is NaN plus review (Review Focus #1). Test in Task 3.
5. **Segments with few or no matched features, and features outside every segment:** `segment_percentile` is NaN, and `n_matched` is reported per segment so the engineer can see a thin sample. No minimum count is invented (spec §10.4). Test in Task 3.

### Task 2: Per-feature growth methods

**Files:** Create `src/ili/growth.py`; Test `tests/test_growth_methods.py`

**Interfaces:**
- Consumes: Task 1 settings; `units.sigma_from_tolerance`.
- Produces (vectorised; NaN in → NaN out; every rate in mpy):
  - `depth_in(depth_pct, wt_in)`
  - `raw_rate(d_prev_in, d_curr_in, dt_yr)` = (d_curr − d_prev) × 1000 / dt
  - `sigma_diff_pct(tool)` = √2 · σ, where σ = `sigma_from_tolerance(depth_tolerance_pct_wt, depth_certainty)`
  - `tolerance_adjusted_rate(d_prev_in, d_curr_in, wt_in, dt_yr, settings)` = max((Δd + k·σ_diff/100·wt) × 1000 / dt, `min_rate_mpy`)
  - `new_feature_rate(d_curr_in, wt_in, dt_yr, settings)` = (d_curr − threshold_pct/100 · wt) × 1000 / dt
  - `full_life_rate(d_curr_in, curr_year, install_year)` = d_curr × 1000 / (curr_year − install_year), NaN where the denominator ≤ 0 or the install year is missing
  - `default_rate(n, settings)`: an array of `default_rate_mpy`, or NaN when it is null

- [ ] Write the failing tests (exact values, `tool` and `growth` from `settings.yaml`):
  - `test_sigma_diff`: √2 × 7.8030 = 11.035 % wall (±1e-3).
  - `test_raw_rate`: 30% → 40% of 0.25 in over 5 yr gives 5.0 mpy, and a 5-point drop gives −2.5.
  - `test_tolerance_adjusted`: Δd 0 over 5 yr, wt 0.25, k 1.28 gives 1.28 · 11.035/100 · 0.25 · 1000/5 = 7.06 mpy. A large drop is floored to 1.0.
  - `test_new_feature`: 18% of 0.25 in at threshold 10, over 5 yr, gives 4.0 mpy.
  - `test_full_life`: 40% of 0.25 in, 2026 vs 1975, gives 1.961 mpy. Install years 2026 and 2030 give NaN (Review Focus #3), and an install year of 2023 gives d / 3.
  - `test_default_rate_null_is_nan`, and 2.0 when set.

### Task 3: Segment percentile, governing rate, length growth, assembled growth table

**Files:** Modify `src/ili/growth.py`; Test `tests/test_growth_table.py`

**Interfaces:**
- Consumes: Tasks 1–2; the M4 match table.
- Produces:
  - `GrowthResult(features: DataFrame, segments: DataFrame, summary: dict)`.
  - `compute_growth(match_table, dt_yr, prev_year, curr_year, pipe, seg_table, settings) -> GrowthResult`.
- `features` has one row per `metal_loss` match-table row with a current side, in table order. Columns:
  - `match_id, match_type, prev_feature_id, curr_feature_id, curr_log_dist_ft, segment_id, history_class`
  - `wt_in, d_prev_pct, d_curr_pct, d_prev_in, d_curr_in, dt_yr, sigma_diff_pct, k_sigma, install_year`
  - `raw_mpy, tolerance_adjusted_mpy, segment_percentile_mpy, new_feature_mpy, full_life_mpy, default_rate_mpy`
  - `governing_mpy, governing_method, needs_review, length_in, length_rate_ipy`
- `history_class`:
  - `matched`: a 1:1 or cluster row with both depths
  - `new`: a `new` row whose pipe `install_year` ≤ `prev_year`
  - `no_history`: everything else, i.e. new pipe (Review Focus #2) or a matched row missing a depth
- Rules:
  - `wt_in`: `curr_wt_nom_in`, falling back to `prev_wt_nom_in`, then to the pipe table's `wt_nom_in` at `curr_log_dist_ft`.
  - `install_year`: from the pipe table via `reference.lookup` with `alignment.anchor_tol_ft`.
  - `raw` and `tolerance_adjusted` apply only to `matched`.
  - `segment_percentile`: the `segment_percentile`-th percentile (`np.percentile`, linear) of `raw_mpy` over `matched` rows in the same segment, negatives included. It is floored at `min_rate_mpy` and applied to every row in the segment. NaN when the segment has no matched rows or the row has no segment.
  - `new_feature` applies only to `new`; `full_life` and `default_rate` are computed for every row.
- Governing: for the row's class, take the max (`np.fmax`, ignoring NaN) over the methods listed in `growth.governing`. `governing_method` names the method that attained it, with ties going in list order. A NaN result gives method None and `needs_review` True.
- Length growth: `none` gives 0. `fixed_rate` gives `length_rate_ipy`. `proportional` gives `length_in × governing_mpy / 1000 / d_curr_in` (the aspect ratio is kept), NaN if `d_curr_in` ≤ 0.
- `segments` (diagnostics): `segment_id, start_ft, end_ft, n_features, n_matched, raw_mean_mpy, raw_median_mpy, raw_p_mpy, pct_negative_raw, governing_max_mpy`.
- `summary`:
  - run ids, Δt, counts by history class and by governing method, `n_needs_review`
  - `pct_negative_raw` over all matched rows
  - `raw_histogram`: `{bin_edges_mpy, counts}`, with bins of `diagnostic_bin_mpy` spanning the matched raw range

### Task 4: Scoring against ground truth and acceptance

**Files:** Modify `src/ili/validation.py`; Test `tests/test_growth_score.py`

**Interfaces:**
- Produces: `score_growth(features, truth) -> dict`.
  - True growth per row:
    - 1:1 and new rows: the `growth_mpy` of the truth row with that `curr_feature_id`
    - cluster rows: the max `growth_mpy` over the truth rows sharing any of the row's `;`-split current ids (the deepest-growing pit governs the envelope)
    - a current id absent from the truth raises `ValueError`
  - Metrics:
    - `raw` on matched rows: `bias_mpy` (mean est − true), `rmse_mpy`, `n`
    - `governing` on all rows with a governing rate: `bias_mpy`, `rmse_mpy`, `n`
    - `conservatism_rate`: the share of rows with governing ≥ true, overall and per history class
    - `n_no_governing`
    - `passes`: `conservatism_rate` ≥ `MIN_GROWTH_CONSERVATISM` = 0.90 (spec §6.5, PLACEHOLDER), as a named constant citing the spec
