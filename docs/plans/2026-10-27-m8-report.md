# ILI Analyzer — Milestone 8 (HTML Report and Excel Dig List) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the outputs M2–M7 already wrote, generate in `outputs/<prev>_vs_<curr>/`:
- a self-contained `report.html` with every section of spec §6.10, a DRAFT banner on every section, and a methods appendix
- `dig_list.xlsx`
- `category_changes.csv`, which classifies the previous run under today's criteria and finds the features that moved to a more severe category
- `run_manifest.json`

**Architecture:**
- `category_change.py` classifies the previous side of each matched feature. It reuses M7's `feature_variables` and `classify` on a match table whose `curr_*` columns are replaced by the `prev_*` ones, with τ = 0 pressures from `strength`.
- `report_data.py` loads and cross-checks every input and builds the report's tables. It does no rendering.
- `report_charts.py` builds plotly figures.
- `report.py` renders a jinja2 template (autoescaped) with plotly.js inlined once, writes the xlsx with openpyxl and the manifest, and runs the CLI.

**Tech Stack:** jinja2 3.1, plotly 7.1, openpyxl 3.1, pandas 3.x (all pinned in `requirements.txt` already).

**Spec:** `docs/SPEC.md` §6.10 (binding), §2 (DRAFT, fully local, traceability), §8 (back-test unity chart), §9 M8. Inputs, all written by earlier milestones:
- the comparison dir: `alignment_summary.json`, `changed_sections.csv`, `match_table.csv`, `match_summary.json`, `growth.csv`, `growth_segments.csv`, `growth_summary.json`, `remaining_life.csv`, `reinspection_intervals.csv`, `remaining_life_summary.json`, `classification.csv`, `classification_summary.json`
- the ingest dir (`outputs/`): `ingest_manifest.json`, `validation_issues.csv`; the standardized prev and curr CSVs
- reference `pipe_properties.csv`, `mop_profile.csv`, `hca_segments.csv`, optional `foreign_crossings.csv` and `digs.csv`

**User decisions (2026-10-27):**
- The previous-run category comes from applying today's criteria to the previous run's reported values at τ = 0. Only the rule categories are compared (immediate / 60_day / 180_day / evaluate); `imp_scheduled` is excluded because there was no growth history at the previous run.
- The dig list holds every classified feature except `evaluate` (immediate, 60_day, 180_day, imp_scheduled).

## Global Constraints

- All M1–M7 constraints hold.
- **Labels:** every output carries `DRAFT – for review by qualified personnel.` (`align_welds.DRAFT_LABEL`). The tool never labels anything final or approved, even with zero pending reviews.
- **Fully local:** `report.html` makes no network requests. plotly.js is inlined once (`plotly.offline.get_plotlyjs()`) and every figure div uses `include_plotlyjs=False`. There are no external `src=`/`href=` URLs, CDNs, web fonts or map tiles. The GPS map is a plain lon/lat scatter with no basemap.
- **Escaping:** jinja2 runs with `autoescape=True`. Vendor text (comments, ids), the line name and file paths are never marked `|safe`. Only the figure divs and plotly.js are.
- **Values:** every value the report shows comes from an input file or settings. Presentation-only numbers (top-N, xlsx colours) are module constants or a new `report:` settings section. Engineering values are never recomputed differently from M5–M7.
- **Blanks:** None/NaN render as an empty cell in HTML and xlsx, never `nan`, `None` or `NaT`.
- **Write order:** all inputs are read and every table is built before any output is written (as in M2–M7).

## Review Focus

1. **Inconsistent or stale inputs:** summaries naming different run ids, or a standardized CSV whose `run_id` differs from them, are a `ValueError`. So is a `classification_summary.json` whose `criteria_sha256` differs from the criteria file now in use (the categories and the methods appendix would disagree). Test in Task 2.
2. **Missing optional inputs:** no `digs.csv` means the unity chart is replaced by "not provided". Without crossings, the report says so. A run with no lat/lon gets no map and a note. A dig id that is not in the current run is listed as unmatched, not an error. Never a crash. Test in Tasks 3 and 5.
3. **Hostile text:** a vendor comment, feature id or `--line-name` containing `<script>` appears escaped in `report.html`. Test in Task 5.
4. **Empty results:** with zero immediate features the executive summary says so; with an empty dig list the xlsx still has its header, filter and freeze; zero pending reviews means no warning, but the report is still DRAFT. Test in Tasks 5 and 6.
5. **Blank values in the dig list:** dents and gouges have no RL, P_F or growth, and an RL can be NaN. Such rows rank after every finite RL in their category and show empty cells in both outputs. Test in Tasks 3 and 6.

    - `mop_psig` is `mop` at `curr_log_dist_ft`; `od_in` and `smys_psi` come from `pipe` there
    - `assessed_dt` = `assessed_depth_in` / `wt_in`
    - `burst_psig` and `safe_psig` use the `strength.method` of settings on the assessed depth and length
    - `dig_required_by_remaining_life` False, `repair_by_date` None, `needs_review` False, `review_reasons` None
  - `CategoryChangeResult(table, previous)`, where `previous` is the prev `ClassificationResult.table`.
  - `category_changes(match_table, remaining_life, classification, curr_std, pipe, mop, segments, crossings, settings, criteria, prev_run_date) -> CategoryChangeResult`
    - `table` columns: `match_id, match_type, prev_feature_id, curr_feature_id, feature_type, prev_depth_pct_assessed, curr_depth_pct_assessed, prev_p_fail, curr_p_fail, prev_rule_category, prev_governing_rule, prev_triggered_rules, prev_rules_not_evaluable, curr_rule_category, curr_governing_category, curr_governing_rule, moved_more_severe`
    - `*_rule_category` maps `imp_scheduled` → `evaluate`
    - `moved_more_severe` = curr rule category ranks above the prev one in `CATEGORY_PRIORITY`
    - Rows are in match-table order. A feature type that changed between runs (e.g. dent → metal_loss) keeps the curr type and both categories.
