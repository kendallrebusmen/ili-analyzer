# ILI Analyzer — Milestone 7 (Repair Classification) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classify every current-run anomaly (metal loss, dent, gouge) against the 49 CFR 195.452(h)(4) rules of spec §6.8. The rules are read from `config/repair_criteria.yaml` and evaluated by a safe expression evaluator. Assign the governing category (`immediate` > `60_day` > `180_day` > `imp_scheduled` > `evaluate`) and compute due dates from the discovery date. Write `classification.csv` and `classification_summary.json`. Every §6.8 rule is implemented, with tests just below, at, and just above its threshold.

**Architecture:**
- `src/ili/rules.py` is a small safe expression language: an `ast`-parsed whitelist, never `eval`. Its logic is three-valued (Kleene): an unknown input (None) gives an unknown result unless the rest of the expression decides the answer.
- `src/ili/classify.py` builds one variable record per current anomaly from M4, M6, the current run and the reference files. It applies the HCA or non-HCA rule set, collects triggered and not-evaluable rules, picks the governing category, and computes due dates.
- `repair_criteria.yaml` carries the full §6.8 HCA rule set, plus a PLACEHOLDER non-HCA rule set (spec: operator-defined from the IMP).

**Tech Stack:** Python `ast`, pandas 3.x, pydantic config.

**Spec:** `docs/SPEC.md` §6.8 (binding), §7.1 `classification`, §7.2, §8 (each rule tested just below, at and just above its threshold), §9 M7, §10.7 (non-HCA criteria open), §2 (DRAFT, traceability). Inputs:
- M4 `match_table.csv`, for dents and gouges and every current anomaly
- M6 `remaining_life.csv`, for metal-loss strength, assessed depth, MOP and the dig flag
- the M2 current standardized CSV, for girth-weld positions and the run date
- reference `pipe_properties.csv` (`od_in`), `hca_segments.csv` and `foreign_crossings.csv`

## Global Constraints

- All M1–M6 constraints hold. Every engineering value is in `config/settings.yaml` or `repair_criteria.yaml`, with comments. The regulatory thresholds live **in the criteria file's conditions** (e.g. `> 80`, `> 6`), not in code. Every output carries `DRAFT – for review by qualified personnel.` The summary records the criteria file's `version` and sha256 (spec §2 traceability).
- **Condition expressions are never passed to `eval`/`exec`/`compile` of user text.** Only the whitelisted AST nodes are interpreted, and only names in the published variable vocabulary are allowed. An unknown name or a disallowed construct is a load-time `ValueError` naming the rule.
- Rules are evaluated at τ = 0 on assessed, tolerance-adjusted values (spec §6.8):
  - metal-loss and gouge depth = reported + `tool.depth_tolerance_pct_wt`, capped at 100% (the same `strength.assessed_depth_in` basis M6 uses)
  - dent depth is as reported (the spec defines no dent tolerance; recorded in DECISIONS)
- Dent position: top of pipe ⇔ `clock_min >= 480 or clock_min <= 240` (spec §6.8, verbatim).
- Undefined inputs become PLACEHOLDER settings with **null defaults**, which produce *unknown*, never a guessed value:
  - girth-weld proximity (exists)
  - crossing proximity (exists)
  - seam clock position (new)
  - general corrosion size (new)
  - widespread circumferential extent (new)

  A rule that is unknown for a feature is listed in `rules_not_evaluable` and sets `requires_review`. It never silently passes.
- Category priority: `immediate` > `60_day` > `180_day` > `imp_scheduled` > `evaluate`. Every current anomaly gets at least `evaluate` (spec (h)(4)(iv)). A metal-loss feature with M6 `dig_required_by_remaining_life` gets `imp_scheduled` (spec: "Features flagged by remaining life").
- A feature outside every segment uses the HCA rule set (conservative) and is flagged.

## Review Focus

1. **Unknown inputs:** an unknown that cannot change the outcome must not flag (e.g. `depth > 50 and near_crossing` with depth 30 is False, not unknown). An unknown that could trigger a rule must flag. Test in Tasks 1 and 4.
2. **Expression-language safety:** attribute access, calls, subscripts, comprehensions, lambdas, f-strings, `**`, very long or deeply nested expressions, and names outside the vocabulary are all rejected at load. Test in Task 1.
3. **Threshold edges:** every rule just below, at, and just above its threshold, including strict `>` as written in the regulation (80% is not immediate; 80.0001% is). Test in Task 2.
4. **Discovery date:**
   - When missing, use assessment date + 180 days with a prominent warning in stdout, the summary and a column.
   - A discovery date before the assessment date, or more than 180 days after it, is an error.

   Test in Task 4.
5. **Mixed feature types and missing M6 rows:** a dent has no RL or pressure; a metal-loss feature missing from remaining_life.csv gets unknown pressures (IMM-2/D180-4 not evaluable, flagged). Never a crash, never a silent pass. Test in Tasks 3 and 4.

### Task 1: Safe expression evaluator

**Files:** Create `src/ili/rules.py`; Test `tests/test_rules.py`

**Interfaces:**
- Produces:
  - `UNKNOWN = None`
  - `compile_condition(text, names: set[str]) -> Condition`. It parses with `ast.parse(text, mode="eval")` and validates every node against the whitelist:
    - `Expression, BoolOp(And/Or), UnaryOp(Not/USub/UAdd), BinOp(Add/Sub/Mult/Div), Compare(Lt/LtE/Gt/GtE/Eq/NotEq/In/NotIn)` (chained compares allowed)
    - `Name` (must be in `names`)
    - `Constant` (int/float/bool/str/None)
    - `Tuple` or `List` of constants (only as the right side of `in`)

    Anything else, or text longer than `MAX_CONDITION_CHARS = 500`, or nesting deeper than `MAX_DEPTH = 32`, raises `ValueError` naming the construct.
  - `Condition.evaluate(variables: dict) -> bool | None`. This is Kleene logic:
    - an arithmetic or comparison with a None or NaN operand gives None
    - `and`: any False → False, else any None → None, else True
    - `or`: any True → True, else any None → None, else False
    - `not None` → None
    - division by zero gives None
  - `Condition.names` (the variables it references).
- [ ] Write the failing tests:
  - Arithmetic and comparison: `"a > 80"`, `"0 < a <= 6"`, `"a / b * 100 > 3"`, and `"t in ('gouge','dent')"`.
  - The Kleene table for and, or and not, with None, including short-circuits that decide: `False and None` → False, `True or None` → True.
  - NaN treated as unknown.
  - Division by zero gives None.
  - Rejections (Review Focus #2): `"__import__('os')"`, `"a.b"`, `"f(a)"`, `"a[0]"`, `"[x for x in a]"`, `"lambda: 1"`, `"a ** 2"`, `"x if a else y"`, an unknown name, 501 characters, and nesting 40 deep. Each raises `ValueError`.
  - `test_no_eval_used`: grep the source of `ili.rules` for `eval(`, `exec(` and `compile(`. Assert none appear outside `ast.parse`.
- [ ] Run them and see FAIL. Implement. Run and see PASS. Commit `feat(classify): safe three-valued condition evaluator`.

### Task 3: Feature variables

**Files:** Create `src/ili/classify.py`; Test `tests/test_classify_vars.py`

**Interfaces:**
- Produces: `feature_variables(match_table, remaining_life, curr_std, pipe, segments, crossings, settings) -> pd.DataFrame`.
  - One row per current-run anomaly in `match_table`: types metal_loss, dent and gouge, rows with a current side (`matched_1to1`, `matched_cluster`, `new`), in table order.
  - Columns: `match_id, curr_feature_id, segment_id`, every `VARIABLES` name, plus `upstream_needs_review, upstream_review_reasons`.
- Rules:
  - **Pressures and dig flag:** metal-loss rows take `p_fail = burst_psig`, `p_safe = safe_psig`, `mop_local = mop_psig`, `depth_pct_assessed = assessed_dt × 100`, `wt_in` and `dig_required_by_remaining_life` from remaining_life.csv by `match_id`. A metal-loss row missing there gets None for the pressures and the dig flag (Review Focus #5).
  - **Gouges:** `depth_pct_assessed` via `strength.assessed_depth_in` on the match table's curr depth and wall.
  - **Dents:**
    - `dent_depth_pct_od = dent_depth_in / od_in × 100`
    - `dent_metal_loss = curr_dent_metal_loss OR curr_depth_pct > 0`, None only if both are unknown
    - pressures are None and unused
  - **Position and geometry:**
    - `od_in` from the pipe table at `curr_log_dist_ft` (`reference.lookup`)
    - `top_of_pipe` per spec (None when the clock is missing)
    - `could_affect_hca` from the segments table; outside every segment gives True plus the reason `no_segment`
  - **Proximity flags** (unknown when their setting is null):
    - `near_girth_weld`: the edge distance (|x − nearest weld| × 12 − length/2, in inches) to the nearest current-run girth weld is ≤ `girth_weld_proximity_in`
    - `near_foreign_crossing`: |x − crossing| ≤ `crossing_proximity_ft`
  - **Seam and size flags:**
    - `seam_interaction` = the vendor flag OR (the seam clock overlap within `seam_clock_tol_min` when `seam_clock_min` is set). It is unknown only if the vendor flag is unknown and the seam position is null.
    - `general_corrosion` and `widespread_circumferential` follow their settings, and are unknown when the setting is null.
  - **Manual flags:** `manual_immediate` and `field_crack_confirmed` are False. M9 will supply them; documented.
  - **Upstream review:** `upstream_needs_review` = M4 needs_review OR M6 needs_review.

### Task 4: Classification and due dates

**Files:** Modify `src/ili/classify.py`; Test `tests/test_classify.py`

**Interfaces:**
- Produces:
  - `ClassificationResult(table, summary)`
  - `classify(variables, criteria, settings, assessment_date, discovery_date=None) -> ClassificationResult`
- `table` columns: the variables, then:
  - `rule_set` (`hca` | `non_hca` | `hca_assumed`)
  - `triggered_rules` (`;`-joined in criteria-file order)
  - `rules_not_evaluable`
  - `governing_category`, `governing_rule`
  - `requires_review`, `review_reasons`
  - `discovery_date`, `discovery_date_source` (`entered` | `latest_permissible`)
  - `due_date`
  - `action_note`
- Rules:
  - **Rule set and evaluation:** use the rules whose `applies_to` matches the feature (`hca` when `could_affect_hca`, else `non_hca`; `all` always) and whose `feature_types` include the feature. Evaluate each: True is triggered; None is not evaluable.
  - **Governing category:** the highest-priority triggered rule. With none: `imp_scheduled` if `dig_required_by_remaining_life` is True, else `evaluate`. `governing_rule` is the first triggered rule in file order within the governing category, or `REMAINING_LIFE` / `EVALUATE`.
  - **`requires_review`:** any triggered rule with `requires_review`, OR any not-evaluable rule, OR upstream review, OR `no_segment`. `review_reasons` appends `rule_review`, `rule_not_evaluable` and `no_segment` to the upstream reasons, de-duplicated.
  - **Discovery and due dates:**
    - The discovery date comes from the argument (`entered`), or else assessment date + `discovery_max_days` (`latest_permissible`).
    - A discovery date before the assessment, or more than `discovery_max_days` after it, is a `ValueError`.
    - Due dates: `immediate` is the discovery date; `60_day` and `180_day` are discovery + `due_days[...]`; `imp_scheduled` is M6's `repair_by_date` (None if unknown, which flags); `evaluate` is None.
  - **`action_note`:** for `immediate`, the spec text: "Requires temporary pressure reduction or shutdown until repaired." Otherwise None.
- `summary`:
  - criteria version and sha256
  - counts by category and by rule, `n_requires_review`, `n_not_evaluable` by rule
  - discovery date and source, plus `discovery_warning` text when the source is `latest_permissible`
