# ILI Analyzer — Milestone 2 (Ingestion and Vendor Maps) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Load any vendor tally (CSV or Excel) through a YAML vendor map into the standard schema. Every row that fails validation goes to `outputs/validation_issues.csv` with a reason; no row is ever dropped silently.

**Architecture:** `src/ili/ingest.py` holds four parts:
- `VendorMap`, a pydantic model of a vendor-map YAML
- `read_tally`, which reads the raw file as strings
- `standardize`, which renames columns, converts units, parses clocks, and maps vocabulary
- `validate`, which splits the result into clean rows and issue rows

Then `ingest_tally` composes them, and a CLI writes `outputs/standardized/<run_id>.csv` plus the combined `outputs/validation_issues.csv`. The M1 generator's `SynthResult.prev_std`/`curr_std` are the oracle: ingesting the synthetic vendor files must reproduce them within the vendor rounding.

**Tech Stack:** pandas 3.1, openpyxl, pydantic 2, PyYAML; reuses `ili.units`, `ili.schema`.

**Spec:** `docs/SPEC.md` §5.1 and §6.2; M1 decisions in `docs/DECISIONS.md`.

## Global Constraints

- All M1 global constraints hold: use the venv python, DRAFT labelling, synthetic data only, no network, and record every interpretation in `docs/DECISIONS.md`.
- Units are converted at ingestion to ft / in / % of wall / clock minutes 0–719.
- Clock parsing must support **hh:mm, decimal hours, and degrees** (§6.2).
- Validation (§5.1) covers these, and each failing row goes to `validation_issues.csv`, excluded from the standard output:
  - required fields present
  - depth 0–100
  - clock in range
  - girth welds monotonic in log distance
- Raw files are read as strings (`dtype=str`), so Excel integer ids and blank cells are never coerced to floats like `"1.0"`.
- Test command: `.\.venv\Scripts\python.exe -m pytest tests -q`

## Review Focus

1. **CSV saved by Excel with a UTF-8 BOM.** The first header becomes `﻿Feature No`. Read with `encoding="utf-8-sig"`. Test in Task 2.
2. **Vocabulary with stray whitespace/case** (`"metal loss "`). Map after `strip().casefold()`. Test in Task 2.
3. **A mapped column absent from the file.** This is a structural error, not a row issue: raise `ValueError` naming the missing column and the map. Test in Task 2.
4. **An out-of-order or duplicated girth weld.** The two welds of the offending pair both go to issues; the rest of the run still ingests. Test in Task 3.
5. **Unparseable numbers or flags** (`"12,3"`, `"maybe"`). These are row issues naming the field and raw value, never NaN passed through silently. Test in Task 3.

### Task 3: Validation

**Files:** Modify `src/ili/ingest.py`; Test `tests/test_ingest_validate.py`

**Interfaces — Produces:** `validate(std: pd.DataFrame, run_id: str) -> tuple[pd.DataFrame, pd.DataFrame]`, which returns clean rows and issue rows (same issue columns). It checks these reasons:
- `missing_required` (`feature_id`, `feature_type`, `log_dist_ft`)
- `depth_out_of_range` (outside 0–100)
- `clock_out_of_range` (outside 0–719, reachable only for numeric formats before wrapping is refused)
- `duplicate_feature_id` (every occurrence after the first)
- `girth_weld_not_monotonic`: both welds of any adjacent weld pair, in file order, whose log distance does not increase

A row with several problems produces one issue line per problem but is excluded once.

**Rulings:**
- **(D) Degrees/decimal hours of exactly 360 / 12.0 wrap to 0.** Values outside [0, 360] / [0, 12] are `clock_out_of_range`, not wrapped.
- **(D) Pair rule for welds.** Both welds of a non-monotonic pair are excluded, because the tool cannot tell which one is wrong. Alignment treats each as a missed weld.

### Task 4: `ingest_tally`, output writing, CLI

**Files:** Modify `src/ili/ingest.py`; Test `tests/test_ingest_cli.py`; Update `README.md`, `docs/DECISIONS.md`

**Interfaces — Produces:**
- `IngestResult(run_id, run_date, standard: DataFrame, issues: DataFrame)`
- `ingest_tally(path, vmap_path, run_date: date | None = None) -> IngestResult`:
  - the run date comes from the argument, else the file; if it is in neither, raise `ValueError("run_date ...")`

- `write_ingest(results: list[IngestResult], out_dir: Path = PROJECT_ROOT/"outputs") -> dict[str, Path]`:
  - writes `standardized/<run_id>.csv` (with `source_row`) and `validation_issues.csv` (all runs; header only if there are none)
  - writes `ingest_manifest.json` (DRAFT label, input sha256, vendor-map sha256, row/issue counts)
- `main(argv) -> int`, CLI `python -m ili.ingest --run TALLY MAP [RUN_DATE] [--run ...] [--out DIR]`. It prints per-run row and issue counts and returns 2 with `error:` on stderr for a `ValueError`. The `--out` default is project-root-relative, which also fixes the M1 minor M5 for this module.
