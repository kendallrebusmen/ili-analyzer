# ILI Analyzer — Milestone 9 (Streamlit Review UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local Streamlit app (`app/streamlit_app.py`) with the five pages of spec §6.11. Review decisions (accept, reject, manual 1:1 or cluster re-pair) and the two manual classification flags persist to CSV logs. The pipeline re-applies them automatically on every rerun. Spec §9 M9 is done when "review decisions persist and re-apply on rerun".

**Architecture:**
- **`review.py`** owns the two append-only decision logs:
  - `reviews.csv` for match decisions
  - `feature_flags.csv` for `manual_immediate` / `field_crack_confirmed`

  It validates them, resolves the effective decision per feature (the latest wins; earlier decisions that share a feature are superseded), and appends atomically.
- **Matching:**
  - `match.match_anomalies` takes the effective decisions and applies them *before* the automated passes.
  - Accepted and manual pairs are forced matches, removed from automation.
  - Rejected features are removed from automation and land as `missing` / `new`.
- **Classification and report:**
  - `classify.feature_variables` reads the effective flags.
  - The report shows the full decision and flag logs with their applied status.
- **`pipeline.py`** runs every stage's CLI in order. The app's Run setup page and a headless rerun both use it.
- **App logic** lives in `src/ili/app_*.py` modules (testable). `app/streamlit_app.py` is a thin page router, tested with `streamlit.testing.v1.AppTest`.

**Tech Stack:** streamlit 1.66 (pinned), plotly, pandas.

**Spec:** `docs/SPEC.md`
- §6.11 (binding)
- §6.4 (review_status `pending | accepted | rejected | manual`; low-confidence matches go to the review queue)
- §6.8 (IMM-5 manual immediate, D180-7 field crack)
- §6.10.3 (pending reviews; review decision log)
- §2 (DRAFT, fully local, traceability)
- §9 M9

**User decisions (2026-10-27):**
- **Reject = split and lock.** The rejected features are excluded from automated matching on every rerun: the previous side becomes `missing` (hint `rejected_by_review`) and the current side `new`.
- **Manual re-pair covers 1:1 and clusters.** A reviewer may pair one previous-run feature with one current-run feature, or several features on either side into a manual cluster.
- **Manual flags are in M9.** They are entered per current-run feature, saved to `feature_flags.csv`, and read by classification on every rerun.

## Global Constraints

- All M1–M8 constraints hold. Every output, page and log carries `DRAFT – for review by qualified personnel.` The app never labels anything approved or final.
- **Fully local:** the app binds to `localhost` and sends no telemetry. `.streamlit/config.toml` sets `browser.gatherUsageStats = false` and `server.address = "localhost"`. Nothing is fetched from a CDN.
- **Logs are append-only.** No code path edits or deletes a log row. A correction is a new row, and the latest row by `decided_utc` wins. A log is written atomically (temp file + `os.replace`) with LF line endings and UTF-8.
- **Decisions are keyed by feature ids, never `match_id`,** because match ids renumber on every rerun. Sets of ids are sorted and `;`-joined, the same convention as the match table's cluster ids.
- **Every decision row records** `reviewer` (required, non-blank free text), `decided_utc` (ISO 8601 UTC), and an optional `note`.
- **Nothing is silently dropped.** A decision that cannot be applied gets an `applied_status` and a reason. The causes are: an unknown feature id, a type rule broken, out of range, or superseded. Every such decision is counted in the match summary, printed by the CLI, and shown in the app and report.

## Review Focus

1. **Stale or conflicting decisions:**
   - A decision naming a feature id absent from the current inputs (re-ingested tally) is `not_applied: unknown_feature`. It is never an exception that blocks the pipeline, and never silently ignored.
   - Two decisions sharing a feature: the later one wins and the earlier one is `superseded`.

   Test in Tasks 1–2.
2. **Idempotence:** rerunning the pipeline twice with the same logs gives byte-identical `match_table.csv` and `classification.csv`. Applying the logs to a fresh match differs from no logs only in the reviewed features. Test in Task 2.
3. **Automation never re-pairs a locked feature:** after a reject, neither feature appears in any matched row. This holds even when it was the only candidate. Test in Task 2.
4. **Concurrent or partial writes:**
   - A log is never left half-written: a failing write leaves the old file intact.
   - A malformed log row (bad decision, blank reviewer, unparseable time) is a `ValueError` naming the file and line. The CLIs exit 2.

   Test in Task 1.
5. **Telemetry and binding:** the shipped config disables usage stats and binds to localhost. Test in Task 5.

### Task 1: Decision logs

**Files:** Create `src/ili/review.py`; Test `tests/test_review_log.py`

**Interfaces:**
- Produces:
  - `REVIEWS_FILE = "reviews.csv"`, `FLAGS_FILE = "feature_flags.csv"`
  - `DECISIONS = ("accept", "reject", "manual")`, `FLAG_NAMES = ("manual_immediate", "field_crack_confirmed")`
  - `REVIEW_COLUMNS = ["decision_id", "decision", "prev_feature_ids", "curr_feature_ids", "reviewer", "decided_utc", "note"]`
    - `decision_id` is `R` + 6 digits, sequential in file order.
    - `prev_feature_ids` and `curr_feature_ids` are sorted and `;`-joined.
  - `FLAG_COLUMNS = ["flag_id", "curr_feature_id", "flag", "value", "reviewer", "decided_utc", "note"]` (`flag_id` is `F` + 6 digits; `value` is `true`/`false`)
  - `load_reviews(path) -> pd.DataFrame` and `load_flags(path) -> pd.DataFrame`. A missing file is an empty frame with the columns; every row is validated. Per-decision rules:
    - accept and manual need ≥ 1 id on each side
    - reject needs both sides non-empty
    - `decided_utc` must parse as a timezone-aware time
  - `append_review(path, decision, prev_ids, curr_ids, reviewer, note=None, now=None) -> dict` and `append_flag(path, curr_feature_id, flag, value, reviewer, note=None, now=None) -> dict` validate, assign the next id, and write atomically.
  - `EffectiveReviews(decisions: pd.DataFrame, superseded: list[str])`
  - `effective_reviews(reviews) -> EffectiveReviews`: process the rows in `decided_utc` order (ties by `decision_id`). A later row that shares any feature id with an earlier effective row supersedes it.
  - `effective_flags(flags) -> dict[tuple[str, str], bool]`: the latest value per (feature, flag).

  - `test_invalid_rows_are_errors` (Review Focus #4): blank reviewer, unknown decision, a reject with one side empty, a naive time, an unknown flag name. Each is a `ValueError` naming the file and line.
  - `test_append_is_atomic`: monkeypatch `os.replace` to raise; the old file is unchanged and no temp file remains.
  - `test_latest_decision_wins_and_supersedes` (Review Focus #1): accept {A1}/{B1}, then manual {A1}/{B2}. The first is superseded; a manual cluster {A3, A4}/{B3} supersedes an earlier reject of {A3}/{B9}.

### Task 2: Apply decisions in matching

**Files:** Modify `src/ili/match.py`; Test `tests/test_match_reviews.py`

**Interfaces:**
- Consumes: `review.effective_reviews`, `load_reviews`
- Produces:
  - `match_anomalies(prev_std, curr_std, weld_map, settings, pipe, repairs=None, reviews: EffectiveReviews | None = None)`
  - New hint `HINTS += ("rejected_by_review",)`
  - `REVIEW_STATUSES = ("pending", "accepted", "rejected", "manual")`
  - Summary keys `counts_by_review_status` and `decisions: {applied, not_applied, superseded}`
  - `MatchResult.decision_status: pd.DataFrame` (`decision_id, decision, applied_status, reason`), one row per log row.
  - `write_matches` also writes `review_status.csv` (`MatchResult.decision_status`, LF line endings) into the comparison dir. It has a header only when there is no log.
  - CLI `--reviews PATH` (default: `<comparison dir>/reviews.csv` when it exists). It prints the decision counts and each not-applied decision.
- Rules (before the automated passes; anomaly rows of the placed frames, by feature id):
  - **Validation**, giving `not_applied` with a reason:
    - every id must exist in its run: `unknown_feature`
    - every id must be an anomaly
    - a 1:1 pair must have the same feature type: `type_mismatch`
    - a multi-member side must be all `metal_loss`: `cluster_type`
    - every member must lie in the same or an adjacent weld-map row as the others: `out_of_range` (adjacency by `wm_row`, as M4's near-weld candidates use)
  - **Forced rows:**
    - Valid accept or manual decisions become rows *before* the automated passes, and their features are removed from automation.
    - A 1:1 row uses `pair_metrics`. A multi-member row uses `_cluster_side_row` and the envelope metrics of `_envelope_pairs`.
    - `review_status` is `accepted` / `manual`, `needs_review` False, and confidence is still computed from the score.
  - **Rejects:** every id of a valid reject is removed from automation. The prev ids become `missing` rows with hint `rejected_by_review`, the curr ids `new`, all with `review_status rejected` and `needs_review` False.
  - **Everything else** is unchanged: pending, needs_review as M4.
- [ ] Write the failing tests, on hand-built placed runs plus the 5-mile synth:
  - `test_no_reviews_is_unchanged`: the table equals M4's output exactly.
  - `test_accept_pins_pair_and_clears_review`
  - `test_reject_splits_and_locks` (Review Focus #3): the pair whose only candidate was each other gives `missing` + `new`; the two ids appear in no matched row.
  - `test_manual_one_to_one_and_cluster`: the rows carry `manual`; the cluster row's ids are joined and its envelope equals `envelope()` of the members.
  - `test_invalid_decisions_not_applied` (Review Focus #1): `unknown_feature`, `type_mismatch`, `cluster_type`, `out_of_range`, each with its reason; the pipeline still produces a full table.
  - `test_every_anomaly_once_with_reviews`: `validation.score_matching`'s table checks are all 0.
  - `test_rerun_is_idempotent` (Review Focus #2): the CLI twice with the same `reviews.csv` gives byte-identical `match_table.csv`.
- [ ] Run them and see FAIL. Implement. Run and see PASS. Commit `feat(match): re-apply review decisions on every run`.
